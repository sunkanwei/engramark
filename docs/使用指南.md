# 使用指南

**[English](user-guide.md) | [简体中文](使用指南.md)**

本文面向 Engramark 的日常使用与维护。安装、升级和卸载见[安装指南](安装指南.md)，架构原理见[架构设计](架构设计.md)。

## 记忆存放在哪里

记忆真源位于 `~/engramark/cards/`，一张卡一个 `.mem` 文件。这是 Engramark 自有的可读卡片格式，不是行业通用标准；普通使用者无需理解或手工编辑。候选、正式、归档和墓碑使用同一目录，状态只看卡片首行：

```text
@8 fact candidate I2 T2 F1.0 2026-01-01
= 示例实体
~ self:agent
# format 1
这是一条自足的记忆标题。
这里是可选正文。
```

| 状态 | 含义 | 默认检索 | 雷达 |
|---|---|---|---|
| `candidate` | 用户明确要求暂存的候选记忆 | 否 | 否 |
| `published` | 已发布的正式记忆 | 是 | 是 |
| `archived` | 保留正文但退出日常使用 | 否 | 否 |
| `tombstone` | 只保留已使用的编号 | 否 | 否 |

编号一经分配就不再复用，所以出现空号或墓碑是正常现象。

## 日常操作

可以直接对接入 Engramark 的 AI 说。只有你明确表达长期保存意图时才会写入；它不使用固定关键词表，也不限制语言，而是理解整句话的意思。普通聊天、临时进度和工具输出不会被记录，也不会反复询问你是否保存。

- “记住……”“帮我记一下……”“以后默认……”“下次别忘……”“把这个存下来”，以及 “remember this”“save this for later”“make a note”“from now on”“don't forget”：都直接写入正式记忆并简短确认；重要路径、身份和长期偏好可以要求锁定。
- “找一下关于……的记忆”：先返回简短的自然语言结果，再按编号读取详情。
- “先存为候选”：只有你明确这样要求时才写候选。
- “看看候选”：列出候选记忆。
- “提升记忆 8”：将候选发布为正式记忆。
- “拒绝记忆 8”：清除候选正文并留下墓碑。
- “归档记忆 8”：保留正文，但退出默认检索和雷达。
- “删除记忆 8”：删除已发布内容；该操作需要再次明确确认，编号仍保留为墓碑。

通过 MCP 或命令行完成变更后，缓存会同步更新，不需要重启 Codex 或 OpenCode。

保存或提议时，Agent 会明确选择适用范围：

- `global`：跨项目长期有效的身份、偏好、路径或流程。
- `project`：只属于当前项目的事实、决策或流程。

项目记忆不会在其他项目中被搜索、读取或修改。宿主不能提供可靠项目目录时，项目范围写入会明确失败，不会自动变成全局记忆。

当前 Codex 若未向 MCP 提供项目根，可在受信任项目目录执行一次：

```sh
~/.local/share/engramark/bin/engramark host-setup \
  project-enable --project "$PWD"
```

撤销该项目覆盖：

```sh
~/.local/share/engramark/bin/engramark host-setup \
  project-disable --project "$PWD"
```

命令只维护项目内 `.codex/config.toml` 的 `mcp_servers.engramark.cwd` 托管块；已有同名配置时会停止，不会覆盖。生效需要新开 Codex 任务。

## 高级维护：手工编辑卡片文件

只有需要人工修复或批量维护时，才建议直接编辑 `cards/*.mem`。编辑时应遵守以下规则：

- 使用 UTF-8、无 BOM、LF 换行；读取时兼容完整 CRLF。
- 首行必须包含编号、类型、状态、重要度、可信度和日期。
- 可信度只接受 `0、0.5、1、1.5、2、2.5、3`。
- 标题前的 `=、~、#` 是结构指令；未知指令会被拒绝。
- 标题之后的正文逐字保留，包括空行、行尾空格和 Unicode。
- Unicode 规范化只用于检索，不会改写正文。
- 实体按规范化值去重，实体顺序没有语义；正文顺序有语义。

手工修改后必须重建缓存：

```sh
~/.local/share/engramark/bin/engramark rebuild
```

这是手工编辑与系统重新建立强一致性的边界。

## 检查与恢复

```sh
# 普通诊断
~/.local/share/engramark/bin/engramark diagnose

# 包含缓存业务一致性检查的完整诊断
~/.local/share/engramark/bin/engramark diagnose --full

# 从卡片真源重新生成缓存
~/.local/share/engramark/bin/engramark rebuild

# 查看并恢复未完成事务
~/.local/share/engramark/bin/engramark recover
```

显式检索遇到坏库、锁超时或人工冲突时会返回错误，不会把故障伪装成“没有匹配”。自动钩子遇到同类故障时不会阻断宿主，而是跳过注入并写入诊断日志。

## 备份与回滚

不要直接复制正在使用的 SQLite 缓存。使用受控命令生成一致快照：

```sh
~/.local/share/engramark/bin/engramark backup /path/to/new-backup
```

快照只包含：

- `cards/`
- `id-sequence`
- `manifest.json`

回滚命令：

```sh
~/.local/share/engramark/bin/engramark rollback /path/to/snapshot --confirm
```

回滚前会校验清单、卡片数量、编号高水位和完整源集合哈希，并自动保存当前安全快照。快照之后出现的新编号会变成墓碑，编号高水位不会回退。

## Codex 与 OpenCode

- Codex：用户输入可由钩子扫描预编译雷达，并注入少量相关自然语言记忆提示。
- OpenCode：安装最小请求雷达插件，但默认关闭；仍可随时通过 MCP 主动检索。确认接受短索引随 OpenCode 对话保存后，可在 `~/engramark/engramark.json` 中把 `opencode.request_radar_enabled` 设为 `true`，再重启 OpenCode 让插件重新读取开关。关闭开关后同样需要重启。未验收版本默认拒绝运行；`allow_unverified_version` 只供升级后的临时兼容性复验，复验结束应立即恢复为 `false`。
- 两者共用同一批卡片、缓存和原生二进制。

雷达提示会在标题和命中原因后附带有界的正文首段微摘要，完整注入严格受字节预算控制。主动调用 `memory_search` 时，只有最终高置信第一名会获得较长正文预览；其余结果以及 SessionStart 仍使用短摘要。看到的摘要或预览不会更新 `last-used`，只有明确读取详情才会更新。

OpenCode 自动雷达只处理 App 编辑器直接提交的普通消息，斜杠命令、附件展开、合成文本和忽略文本均跳过。它不会记录聊天或工具流水，也不会自动保存正式记忆或候选；失败时只是不注入，不影响正常消息和显式 MCP。

## Git 与隐私

真实卡片、状态、缓存、日志和本机运行时均被 `.gitignore` 排除。旧版 `raw/` 也继续忽略，防止历史流水误入仓库。不要使用 `git add -f` 强行加入这些内容。

公开前可以检查：

```sh
cd /path/to/engramark-source
git status --short --ignored
git check-ignore cards/0001.mem state/id-sequence cache/memory.mcache
python3 tests/test_repository_privacy.py
```

## 卸载

卸载会移除程序和宿主接线，并始终保留全部记忆：

```sh
~/.local/share/engramark/bin/uninstall
```

程序不提供自动删除记忆的参数。确实不再需要记忆时，由用户手工处理 `~/engramark/`；重新安装会自动接回保留的内容。
