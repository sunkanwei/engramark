# 使用指南

**[English](user-guide.md) | [简体中文](使用指南.md)**

本文面向第一次使用 Engramark 的用户。安装、升级和卸载见[安装与升级](安装指南.md)；存储与检索原理见[架构设计](架构设计.md)。

## 先了解 Engramark 怎么用

Engramark 不是一个需要单独打开的笔记应用。安装并重启 Codex 或 OpenCode 后，你仍然像平时一样与编码助手对话：明确要求长期记住时，助手才会保存；以后遇到相关问题时，助手可以自动获得简短提示，也可以按你的要求主动查询。

日常使用只需要记住三件事：

- **不会自动记录所有聊天。** 普通问答、临时进度、工具输出和命令历史都不会被保存。
- **直接说人话即可。** 不要求固定口令，也不需要手工调用 MCP 工具。
- **记忆保存在本机。** Codex 与 OpenCode 可以共用同一份记忆，但不同项目的项目记忆彼此隔离。

## 五分钟完成第一次使用

先完成[安装](安装指南.md#安装)，然后彻底退出并重新打开 Codex 或 OpenCode。在一个真实项目目录中开始新任务，并按下面的顺序操作。

### 1. 保存一条项目记忆

对助手说：

> 记住：这个项目默认使用 pnpm，请保存为项目记忆。

正常情况下，助手会简短确认已经保存，并告诉你记忆编号。本例已经在请求中明确指定“项目记忆”，因此它只在当前项目中可见。

### 2. 在新任务中找回它

新建一个任务，再说：

> 查询 Engramark 记忆：这个项目使用什么包管理器？

助手应该先搜索记忆，确认相关内容后回答 `pnpm`。这一步可以同时验证宿主接入、保存、项目识别和检索是否正常。

### 3. 修改它

继续说：

> 把刚才那条记忆改为：这个项目默认使用 pnpm 10。

助手会修改原记忆，而不是再保存一条相互冲突的新记忆。如果上下文不足以确定目标，可以直接带上保存时返回的记忆编号。

### 4. 清理测试记忆

如果这只是一次测试，可以说：

> 删除刚才那条测试记忆。

删除正式记忆需要再次明确确认。删除后正文会被清除，但编号不会复用，这是正常的安全设计。如果内容只是暂时不用，可以选择归档而不是删除。

## 日常怎么使用

下面的话只是示例，不是必须逐字使用的命令。Engramark 根据整句话的意思判断你的意图。

| 你想做什么 | 可以怎样说 | 系统会怎样处理 |
|---|---|---|
| 保存当前项目的约定 | “记住：这个仓库统一使用 pnpm，保存为项目记忆。” | 保存为只属于当前项目的正式记忆 |
| 保存跨项目偏好 | “以后所有项目默认优先使用中文回答，把它记为全局偏好。” | 保存为跨项目可用的正式记忆 |
| 主动找回 | “查一下 Engramark 里关于发布检查清单的记忆。” | 先搜索少量结果，再读取确实相关的正文 |
| 修改旧内容 | “把记忆 18 更新为……” | 修改原记忆，避免新旧内容冲突 |
| 检查需要整理的内容 | “检查一下我的记忆，有没有候选、长期未使用或可能冲突的内容。” | 返回检查摘要，不会自动修改 |
| 暂时退出日常使用 | “归档记忆 18。” | 保留内容，但不再参与默认搜索和自动提示 |
| 永久清除内容 | “删除记忆 18。” | 要求再次确认，然后清除正文并保留已用编号 |

保存后不需要重启宿主。通过助手或命令行完成的修改会立即进入后续查询。

## 什么值得长期保存

适合保存的是以后仍会影响判断、并且不希望每次重新解释的内容：

| 内容 | 示例 | 建议范围 |
|---|---|---|
| 项目约定 | “这个仓库统一使用 pnpm，不提交 npm 锁文件。” | 项目 |
| 架构决策 | “认证由网关统一处理，业务服务不直接解析令牌。” | 项目 |
| 重要路径或别名 | “团队口中的 core 指仓库里的 `packages/core/`。” | 项目 |
| 可重复流程 | “修改数据库结构后必须先生成迁移，再运行兼容性检查。” | 项目 |
| 跨项目个人偏好 | “给我方案后等我确认，再做高风险修改。” | 全局 |
| 稳定的身份或环境信息 | “我的主要开发机使用 Apple Silicon。” | 全局 |

不建议保存：

- 只对当前任务有效的进度、待办和中间结论；
- 可以随时从代码或正式文档准确查到的普通事实；
- 大段日志、完整聊天、构建输出或未经整理的资料；
- 尚未核实的猜测，除非你明确要求先存为候选；
- 密码、访问令牌、私钥或其他敏感凭据。记忆虽然保存在本机，但被检索时仍会进入编码助手的上下文。

一条好记忆应当自足、明确、以后还能看懂。与其保存“以后按这个处理”，不如保存“修改数据库结构后，必须生成迁移并运行兼容性检查”。

## 项目记忆还是全局记忆

最简单的判断方法是：**换到另一个项目后，这条内容还应该生效吗？**

- 如果答案是否定的，使用**项目记忆**。项目技术选型、目录别名、架构决策和仓库工作流通常属于这一类。
- 如果答案是肯定的，使用**全局记忆**。个人沟通偏好、跨项目习惯和稳定环境信息通常属于这一类。

保存时助手必须明确选择范围。项目记忆不能从其他项目中搜索、读取、修改或删除；宿主无法可靠识别当前项目时，项目写入会明确失败，不会悄悄变成全局记忆。

## 自动想起与主动查询

### 主动查询最可靠

需要确定找回某条内容时，直接告诉助手查询 Engramark。问题中最好带上项目名、组件名、路径、技术名词或决策主题，例如：

> 查一下 Engramark 里关于数据库迁移检查的记忆。

“上次那个怎么处理”一类过于模糊的问题可能没有足够线索。没有可靠匹配时，Engramark 会明确表示证据不足，不会把弱关联内容冒充成记忆。

### 自动提示因宿主而异

- **Codex：**安装接线可以在发送普通请求时扫描本机索引；命中后最多提供 3 条简短提示，正文仍由助手按需读取。不相关时不会占用上下文。
- **OpenCode：**主动查询始终可用。自动请求雷达默认关闭，因为自动提示可能随对话消息保存；了解这一影响并愿意开启时，再按后文配置。

自动提示只是便利功能，不保证每个相关问题都会命中。重要信息需要确认时，应当主动要求查询。

## 候选记忆：暂时不确定时再用

候选不是日常保存的必经步骤。只有你明确表示暂时不确定是否长期保留时，才需要说：

> 先存为候选：以后发布前可能需要执行完整性能测试，我之后再确认。

候选不会进入默认搜索或自动提示。之后可以这样处理：

- “检查一下我的记忆。”查看待处理候选和可能需要整理的内容；
- “把记忆 18 转为正式记忆。”让它进入日常搜索；
- “丢弃候选记忆 18。”清除候选内容。

Engramark 不会因为某段信息看起来重要，就擅自创建候选或反复询问你是否保存。

## 纠正、归档和删除

- **内容仍然有效，但表述或细节变了：**修改原记忆。
- **内容暂时不用，但以后可能需要查证：**归档。归档保留正文，但退出默认搜索和自动提示。
- **内容不应继续保留：**删除。删除需要再次确认，正文清除后只留下不再复用的编号。
- **一条记忆被实际结果证明正确或错误：**可以把证据告诉助手。只有存在明确证据时，助手才会记录可信度反馈。

重要路径、身份信息或长期偏好可以在保存时要求锁定。锁定记忆不会因为自动反馈被降低可信度，但仍然可以由你明确修改、归档或删除。

## 备份与恢复

不要直接复制正在使用的 SQLite 缓存。备份应使用 Engramark 提供的一致快照命令。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark backup /path/to/new-backup
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" backup "D:\Backups\engramark"
```

快照只包含文本记忆真源、编号状态和完整性清单，不复制正在使用的缓存。回滚前 Engramark 会验证快照，并自动为当前内容再创建一份安全快照。快照之后出现的新编号会转为墓碑，编号高水位不会回退。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark rollback /path/to/snapshot --confirm
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" rollback "D:\Backups\engramark" --confirm
```

## 助手没有记住时怎么办

按下面的顺序排查：

1. **确认已经重启宿主。** 安装或升级后，旧任务可能仍然使用之前的接线。
2. **明确要求查询。** OpenCode 的自动雷达默认关闭；Codex 的自动提示也可能因为线索不足而不命中。
3. **确认作用范围。** 项目记忆只能在原项目中使用；从其他目录打开的任务看不到它。
4. **使用更具体的问题。** 加上项目名、组件名、路径或决策主题，不要只问“上次那个”。
5. **运行完整诊断。** 它会检查卡片、编号状态、缓存和检索能力。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark diagnose --full
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" diagnose --full
```

如果诊断报告存在未完成事务，可以执行恢复。该命令会检查并以幂等方式重放需要完成的步骤：

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark recover
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" recover
```

如果 Codex 没有向 Engramark 提供可靠的项目根，可以在受信任的项目目录中启用项目覆盖，然后新建 Codex 任务。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark host-setup \
  project-enable --project "$PWD"
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" host-setup `
  project-enable --project (Get-Location).Path
```

不再需要时，将 `project-enable` 改为 `project-disable` 即可撤销。命令只维护项目内 `.codex/config.toml` 中由 Engramark 管理的配置；如果已有同名配置，它会停止而不是覆盖。

## OpenCode 自动提示

OpenCode 的主动 MCP 查询无需额外配置。只有在接受短记忆提示可能随 OpenCode 对话保存后，才建议在配置文件中将 `opencode.request_radar_enabled` 设为 `true`，然后重启 OpenCode。macOS 与 Linux 的配置文件是 `~/engramark/engramark.json`，Windows 是 `%USERPROFILE%\engramark\engramark.json`。

自动雷达只处理 App 编辑器直接提交的普通文本；斜杠命令、附件展开、合成文本和忽略文本都会跳过。它不会记录聊天或工具流水，也不会自动创建记忆。未验收版本默认拒绝运行；`allow_unverified_version` 只适合升级后的临时兼容性复验，完成后应恢复为 `false`。

## 数据位置与高级维护

记忆真源位于 macOS 与 Linux 的 `~/engramark/cards/`，或 Windows 的 `%USERPROFILE%\engramark\cards\`。一张卡对应一个 `.mem` 文件。`.mem` 是 Engramark 自有的可读文本格式，不是行业通用标准；普通使用者无需理解或手工编辑。

状态含义如下：

| 内部状态 | 面向用户的含义 | 默认搜索 | 自动提示 |
|---|---|---:|---:|
| `candidate` | 等待确认的候选记忆 | 否 | 否 |
| `published` | 正在使用的正式记忆 | 是 | 是 |
| `archived` | 保留但退出日常使用 | 否 | 否 |
| `tombstone` | 正文已清除，只保留用过的编号 | 否 | 否 |

只有人工修复或批量维护时，才建议直接编辑 `cards/*.mem`。文件必须使用 UTF-8、无 BOM 和 LF 换行；首行结构字段、指令和值域均需保持有效，正文顺序和 Unicode 内容会原样保留。手工修改后必须运行：

```sh
~/.local/share/engramark/bin/engramark rebuild
```

Windows PowerShell 使用：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" rebuild
```

这一步会从文本真源重新生成派生缓存。更详细的格式、不变量与恢复机制见[架构设计](架构设计.md)。
