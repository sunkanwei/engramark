# 使用指南

**[English](user-guide.md) | [简体中文](使用指南.md)**

本文面向第一次使用 Engramark 的用户。安装、升级、配置和卸载见[安装与升级](安装指南.md)；存储与检索原理见[架构设计](架构设计.md)。

## 先了解一件事

Engramark 不是一个需要单独打开的笔记应用。安装后，你仍然像平时一样与 Codex 或 OpenCode 对话：明确要求长期记住时，助手才会保存；以后遇到相关问题时，助手会根据需要找回。

日常使用只需要记住三点：

- **不会自动记录所有聊天。** 普通问答、临时进度、工具输出和命令历史都不会被保存。
- **直接表达目的即可。** 不要求固定口令，也不需要说出 Engramark、MCP 或任何工具名。
- **记忆保存在本机。** Codex 与 OpenCode 可以共用同一份记忆，不同项目的项目记忆彼此隔离。

## 五分钟完成第一次使用

先完成[安装](安装指南.md#安装)，彻底退出并重新打开 Codex 或 OpenCode，然后在一个真实项目目录中开始新任务。

### 1. 保存一条项目记忆

对助手说：

> 记住：这个项目的包管理器是 pnpm，请保存为项目记忆。

正常情况下，助手会简短确认，并告诉你记忆编号。本例明确选择了“项目记忆”，所以它只在当前项目中可见。

### 2. 在新任务中自然提问

新建一个任务，再问：

> 你还记得这个项目使用什么包管理器吗？

助手应当找回刚才的内容并回答 `pnpm`。这一步可以同时验证安装接入、保存、项目识别和找回是否正常。

### 3. 修改原记忆

继续说：

> 把刚才关于包管理器的记忆改为：这个项目使用 pnpm 10。

助手会更新原记忆，而不是再保存一条相互冲突的内容。如果无法确定你指的是哪条记忆，再带上保存时返回的编号即可。

### 4. 清理测试内容

如果这只是一次测试，可以说：

> 删除刚才那条测试记忆。

删除正式记忆需要再次明确确认。删除后正文会被清除，但编号不会复用。如果内容以后可能还有参考价值，可以选择归档而不是删除。

## 日常怎么说

下面都是自然对话示例，不是必须逐字使用的命令。

| 你想做什么 | 可以怎样说 | 系统会怎样处理 |
|---|---|---|
| 保存项目约定 | “记住：这个仓库统一使用 pnpm，保存为项目记忆。” | 只在当前项目中长期保留 |
| 保存个人偏好 | “以后所有项目都优先用中文回答，把它记为全局偏好。” | 跨项目长期保留 |
| 找回以前的决定 | “发布前需要检查什么？” | 查找相关记忆，并在证据足够时回答 |
| 修改旧内容 | “把关于包管理器的记忆改为使用 pnpm 10。” | 更新原记忆，避免新旧内容冲突 |
| 整理记忆 | “帮我看看有没有过期、冲突或待确认的长期记忆。” | 返回检查结果，不会自动修改 |
| 暂时不用 | “把关于旧发布流程的记忆归档。” | 保留内容，但退出日常找回和自动提示 |
| 永久清除 | “删除关于旧测试服务器的记忆。” | 确认目标后再次请求删除确认 |

保存或修改后不需要重启。新的请求会立即看到变化。

## 什么值得长期保存

适合保存的是以后仍会影响判断、并且不希望每次重新解释的内容：

| 内容 | 示例 | 建议范围 |
|---|---|---|
| 项目约定 | “这个仓库使用 pnpm，不提交 npm 锁文件。” | 项目 |
| 架构决策 | “认证由网关统一处理，业务服务不直接解析令牌。” | 项目 |
| 重要路径或别名 | “团队口中的 core 指 `packages/core/`。” | 项目 |
| 可重复流程 | “修改数据库结构后，先生成迁移，再运行兼容性检查。” | 项目 |
| 跨项目偏好 | “高风险修改先给方案，等我确认后再执行。” | 全局 |
| 稳定环境信息 | “我的主要开发机使用 Apple Silicon。” | 全局 |

不建议保存：

- 只对当前任务有效的进度、待办和中间结论；
- 可以随时从代码或正式文档准确查到的普通事实；
- 大段日志、完整聊天、构建输出或未经整理的资料；
- 尚未核实的猜测，除非你明确要求先存为候选；
- 密码、访问令牌、私钥或其他敏感凭据。

> [!WARNING]
> 记忆虽然保存在本机，但被找回时仍会进入编码助手的上下文。不要把本地存储误解成适合保存密码或密钥。

一条好记忆应当自足、明确，以后还能看懂。与其保存“以后按这个处理”，不如保存“修改数据库结构后，先生成迁移，再运行兼容性检查”。

## 项目记忆还是全局记忆

最简单的判断方法是：**换到另一个项目后，这条内容还应该生效吗？**

- 如果答案是否定的，使用**项目记忆**。项目技术选型、目录别名、架构决策和仓库工作流通常属于这一类。
- 如果答案是肯定的，使用**全局记忆**。个人沟通偏好、跨项目习惯和稳定环境信息通常属于这一类。

保存时必须明确选择作用范围。项目记忆不能从其他项目中查找、读取、修改或删除；当前项目无法可靠识别时，项目写入会明确失败，不会悄悄变成全局记忆。

## 自动想起与主动查找

### 需要确认时直接问

平时不需要先发出“搜索记忆”命令。直接提出问题即可：

> 之前定下的数据库迁移流程是什么？

问题中最好带上项目名、组件名、路径、技术名词或决定主题。“上次那个怎么处理”一类问题可能没有足够线索；没有可靠匹配时，助手应当明确表示不确定，而不是把弱关联内容说成已经记住的事实。

如果助手没有意识到你是在询问长期内容，可以补充一句：

> 从以前保存的长期记忆里找一下。

这仍然是自然语言，不需要知道产品名或底层工具。

### 自动提示因编码助手而异

| 编码助手 | 默认行为 |
|---|---|
| Codex | 相关请求可以自动获得少量简短提示，完整内容仍按需读取 |
| OpenCode | 自然语言找回可用；自动请求提示默认关闭 |

自动提示只是便利功能，不保证每个相关问题都会命中。答案很重要时，应当明确问起以前保存的决定或偏好。OpenCode 自动提示的隐私边界和开启方法见[安装指南](安装指南.md#opencode-自动提示)。

## 候选记忆：暂时不确定时再用

候选不是日常保存的必经步骤。只有暂时不确定内容是否值得长期保留时，才需要说：

> 先存为候选：以后发布前可能需要执行完整性能测试，我之后再确认。

候选不会进入日常找回或自动提示。之后可以：

- 说“帮我看看有哪些待确认的长期记忆”来查看候选；
- 说“把关于性能测试的候选转为正式记忆”让它进入日常使用；
- 说“丢弃关于性能测试的候选”清除候选内容。

Engramark 不会因为某段信息看起来重要，就擅自创建候选或反复询问你是否保存。

## 修改、归档还是删除

- **内容仍然有效，只是细节变了：**修改原记忆。
- **现在用不到，但以后可能需要查证：**归档。内容继续保留，但不再参与日常找回和自动提示。
- **内容不应继续保留：**删除。删除需要再次确认，正文清除后只保留已经使用过的编号。
- **实际结果证明一条记忆正确或错误：**把证据告诉助手。只有存在明确证据时，系统才会调整可信度。

重要路径、身份信息或长期偏好可以在保存时要求锁定。锁定内容不会被自动反馈降低可信度，但仍然可以由你明确修改、归档或删除。

## 备份与恢复

不要直接复制正在使用的数据库文件。使用 Engramark 提供的一致快照命令。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark backup /path/to/new-backup
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" backup "D:\Backups\engramark"
```

回滚前 Engramark 会验证快照，并自动保存当前状态。快照之后新建的编号不会被重新分配。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark rollback /path/to/snapshot --confirm
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" rollback "D:\Backups\engramark" --confirm
```

## 找不到以前的内容怎么办

按下面的顺序检查：

1. **安装或升级后是否重启了 Codex/OpenCode。** 已经打开的旧任务可能仍在使用旧接入。
2. **是否在正确的项目中。** 项目记忆只能从原项目中使用。
3. **问题是否足够具体。** 加上项目、组件、路径或决定主题，不要只问“上次那个”。
4. **OpenCode 是否只是关闭了自动提示。** 关闭自动提示不影响自然语言找回。
5. **让助手从长期记忆中查找。** 这可以排除它没有识别出回忆意图的情况。

仍然无法使用时，按照[安装指南的故障排查](安装指南.md#故障排查)运行诊断并检查项目接入。

## 数据存放在哪里

| 系统 | 私人数据目录 |
|---|---|
| macOS、Linux | `~/engramark/` |
| Windows | `%USERPROFILE%\engramark\` |

原始记忆位于其中的 `cards/` 目录，一条记忆对应一个 `.mem` 文本文件。`.mem` 是 Engramark 自己的可读格式，不是行业通用格式；普通用户不需要理解或手工编辑。

程序文件与这个目录分开，所以重新安装或卸载程序不会自动删除记忆。格式、状态和手工修复方法见[架构设计](架构设计.md#4-记忆文件与状态)。
