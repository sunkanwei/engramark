# 维护者发布指南

**[English](release-guide.md) | [简体中文](发布指南.md)**

本文只面向维护者，说明如何构建、验证并发布 Engramark 候选版本。使用者安装、升级和卸载见[安装指南](安装指南.md)。

## 发布模型

Engramark 采用单二进制、原生平台分别构建的发布模型：

- macOS Apple Silicon；
- macOS Intel；
- Linux x86_64；
- Windows x86_64。

四个平台必须在各自原生 runner 上完成构建和运行验证。不得用交叉编译结果代替原生能力探针、完整测试和安装生命周期。

程序与私人数据保持分离。发布包只包含可替换程序、宿主适配、默认配置、文档、许可证和供应链元数据，不包含任何真实记忆、缓存或本机状态。

## 版本准备

发布前确认：

1. 根目录 `VERSION` 与 `rust/Cargo.toml` 的版本一致。
2. 目标标签必须是 `v<版本>`。
3. 工作区只包含预期变更，不含真实记忆、凭据或本机产物。
4. 面向用户的行为、支持边界和文档已经同步。
5. 金样变化经过明确评审，并同时更新实现、清单与说明。

## 本机构建

只构建当前机器可以原生运行和验证的目标：

```sh
python3 packaging/build_release.py --target macos-arm64
```

构建器执行锁定依赖的 release 构建和能力探针，然后生成：

```text
dist/engramark-<版本>-<目标>.tar.gz
dist/engramark-<版本>-windows-x86_64.zip
dist/checksums.txt
```

每个候选包包含：

- 原生 `engramark` 或 `engramark.exe`；
- 默认配置、宿主适配器和中英文文档；
- `SBOM.json`；
- Rust 依赖与 Unicode 数据的上游许可证；
- `MANIFEST.tsv` 逐文件类型、大小与 SHA-256 清单。

Linux 产物在 Ubuntu 22.04 构建，并拒绝高于 glibc 2.35 的符号需求。macOS 产物固定声明 13.0 deployment target；该声明不是某个具体系统版本的原生运行证明。

## 发布前验证

日常完整测试：

```sh
python3 tests/run.py
python3 tests/test_repository_privacy.py
```

10,006 张卡的非 CI 规模验收：

```sh
ENGRAMARK_SCALE_CARDS=10006 python3 tests/test_retrieval_scale.py
```

静态与供应链检查：

```sh
ruff check tests packaging
shellcheck install.sh bin/install.sh bin/uninstall bin/uninstall.sh
cargo deny --manifest-path rust/Cargo.toml check advisories licenses sources
git diff --check
```

本机原生安装生命周期：

```sh
python3 packaging/build_release.py --target <当前原生目标>
python3 tests/test_install_lifecycle.py
```

生命周期在隔离用户目录中验证：危险归档拒绝、安装、宿主接线、MCP、钩子/雷达、检索、写入、备份、升级重装、卸载，以及卸载后记忆完整保留。

## GitHub 发布候选

推送与 `VERSION` 一致的 `v*` 标签后，GitHub Actions 会：

1. 运行静态、文档、隐私和供应链门禁。
2. 在四个原生 runner 上分别运行完整测试、能力探针、打包和安装生命周期。
3. 把相同候选包交给较新系统复验。
4. 汇总统一 `checksums.txt`。
5. 为产物生成 GitHub 构建来源证明。
6. 创建未公开的 GitHub Release 草稿。

自动流程不会直接公开版本。维护者必须确认四个平台的构建、兼容性复验、校验和、来源证明和附件完整后，再人工公开草稿。

## 完整性、来源与代码签名

当前公开分发使用三层校验：

- 外层 `checksums.txt` 检查下载内容；
- 包内 `MANIFEST.tsv` 检查展开后的每个文件；
- GitHub 构建来源证明确认产物由本仓库工作流生成。

这些措施不等同于操作系统代码签名。当前公开包没有 macOS Developer ID 签名、公证或 Windows 代码签名，因此用户仍可能看到来源或未知发布者警告。公开版本说明和安装文档必须如实保留这一边界。

如果以后面向受企业策略管控的设备分发，可另行引入平台代码签名；在签名流程完成前，不得把校验和或来源证明描述为代码签名。

## 发布后检查

公开 Release 后至少确认：

- 默认下载链接能取得四个平台的正确候选包和统一校验清单；
- 安装脚本能解析资产名称并选择当前平台；
- Release 页面包含构建来源证明；
- `README.md` 与安装指南指向当前有效命令；
- 标签、`VERSION`、Cargo 包版本和文件名一致；
- `main` 上没有被遗漏的发布修复。

项目本体采用 MIT 许可证。每个候选包还必须携带依赖 SBOM 和上游许可证集合。
