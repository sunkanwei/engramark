# 发布指南

Engramark 采用单二进制发布模型。程序位于 `~/.local/share/engramark/`（Windows 为 `%LOCALAPPDATA%\Engramark\`），私人记忆位于 `~/engramark/`（Windows 为 `%USERPROFILE%\engramark\`）。

## 安装与重装

```sh
curl -fsSL https://raw.githubusercontent.com/sunkanwei/engramark/main/install.sh -o /tmp/engramark-install.sh
sh /tmp/engramark-install.sh
```

Windows PowerShell：

```powershell
$script = Join-Path $env:TEMP "engramark-install.ps1"
Invoke-WebRequest https://raw.githubusercontent.com/sunkanwei/engramark/main/install.ps1 -OutFile $script
& $script
```

安装包是单一原生二进制（内嵌 SQLite）。安装器先拒绝危险归档条目，再按 `MANIFEST.tsv` 复验条目白名单、大小和逐文件哈希；随后运行 SQLite 能力自检与宿主预检，获取安装锁，切换固定程序目录并保留回退版本，准备数据缓存、执行冒烟，最后以事务方式接入 Codex 和 OpenCode。任一步失败会恢复安装前程序状态；重装不会删除或覆盖记忆。Windows 使用 `install.ps1`。

升级完成后请重启 Codex/OpenCode 宿主：仍在运行的旧会话可能继续引用已被替换的旧程序路径。

## 卸载

```sh
~/.local/share/engramark/bin/uninstall
```

卸载只移除程序和宿主接线，始终保留 `~/engramark/`。程序不提供自动删除记忆的参数；确实不再需要记忆时，由用户手工处理数据目录。

Windows 使用：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\uninstall.ps1"
```

## 构建

```sh
python3 packaging/build_release.py --target macos-arm64
```

构建器只构建显式指定的当前原生目标，执行 `cargo build --release --locked` 和能力探针，然后生成压缩包、SBOM、第三方许可证集合、逐文件清单与 `dist/checksums.txt`：

```text
dist/engramark-<版本>-macos-arm64.tar.gz
dist/checksums.txt
```

四个目标由 GitHub Actions 在原生 runner 上分别构建，再把完全相同的候选包交给复验作业。Linux 基线为 Ubuntu 22.04/glibc 2.35；macOS 产物固定声明 13.0 deployment target。arm64 会在 macOS 14 实际运行，x86_64 会在公开仓库可用的 macOS 15 Intel 标准 runner 实际运行；因此自动化证据只能证明 arm64 的 macOS 14 运行兼容性和 x86_64 的 macOS 15 运行兼容性，不能把 deployment target 单独当作 x86_64 的 macOS 14 实机证明。不提供会掩盖原生验证要求的 `--target all`，未完成对应原生作业的产物不得宣称支持。

发布前运行：

```sh
python3 tests/run.py
python3 tests/test_repository_privacy.py
ENGRAMARK_SCALE_CARDS=10006 python3 tests/test_retrieval_scale.py
shellcheck install.sh bin/install.sh bin/uninstall bin/uninstall.sh
cargo deny --manifest-path rust/Cargo.toml check advisories licenses sources
```

## GitHub Release

推送与 `VERSION` 一致的 `v*` 标签后，工作流在四个原生 runner 上分别运行完整测试、能力探针和安装生命周期，汇总统一校验清单并生成 GitHub 构建来源证明。自动流程只创建未公开的 Release 草稿，不会把未签名产物直接发布给第三方。

项目采用 MIT 许可证。公开草稿前必须另行完成 macOS Developer ID 签名与公证、Windows 代码签名，并复验签名后的最终文件；仅明确的私有离线分发可以接受未签名包。相同 Release 中的 SHA-256 只能校验传输完整性，不能替代发布者认证。
