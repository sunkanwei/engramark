# 安装与升级

**[English](installation.md) | [简体中文](安装指南.md)**

本文面向 Engramark 使用者，说明支持平台、安装、升级、配置、故障排查和卸载。维护者构建发布候选的流程见[维护者发布指南](发布指南.md)。

## 支持的平台

| 发布目标 | 架构 | 当前原生验证环境 |
|---|---|---|
| macOS | Apple Silicon、Intel | Apple Silicon：macOS 14/15；Intel：macOS 15 |
| Linux | x86_64，glibc 2.35 或更新版本 | Ubuntu 22.04 构建，Ubuntu 24.04 复验 |
| Windows | x86_64 | Windows Server 2022/2025 runner，PowerShell 5.1 与 7 安装生命周期 |

表中的 Windows Server 是自动化验证环境，不表示 Engramark 是服务器应用。没有列出的系统或架构可能可以运行，但不在当前原生验证承诺内。

只有对应平台完成完整测试、能力自检、打包和安装生命周期后，该次产物才被视为受支持。交叉编译或最低系统版本声明不能代替原生运行证据。

## 安装

macOS 与 Linux：

```sh
curl -fsSL https://raw.githubusercontent.com/sunkanwei/engramark/main/install.sh -o /tmp/engramark-install.sh
sh /tmp/engramark-install.sh
```

Windows：以下命令可以粘贴到 PowerShell 5.1 或 7，并会使用系统自带的 Windows PowerShell 5.1 运行安装脚本。

```powershell
$script = Join-Path $env:TEMP "engramark-install.ps1"
Invoke-WebRequest https://raw.githubusercontent.com/sunkanwei/engramark/main/install.ps1 -OutFile $script
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -ExecutionPolicy Bypass -File $script
```

> [!NOTE]
> `-ExecutionPolicy Bypass` 只对本次安装子进程生效，不会永久修改用户的执行策略。单位通过组策略设置的限制仍然优先，必要时需要设备管理员放行。

安装包包含内嵌 SQLite 的单一原生程序，不要求另行安装 Python、Homebrew、数据库或包管理器。

## 安装完成后

安装器会自动接入检测到的 Codex 和 OpenCode。完成后：

1. 彻底退出并重新打开 Codex 或 OpenCode；
2. 在一个项目目录中开始新任务；
3. 对助手说：“记住：这个项目的包管理器是 pnpm，请保存为项目记忆。”

助手确认并返回记忆编号，说明保存接入已经可用。新建任务后再问“你还记得这个项目使用什么包管理器吗？”，可以进一步验证找回与项目识别。

完整的第一次使用流程见[使用指南](使用指南.md#五分钟完成第一次使用)。

## 验证安装

正常使用不要求运行命令行诊断。如果需要确认卡片、编号状态、本机索引和运行能力，可以执行完整诊断。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark diagnose --full
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" diagnose --full
```

命令成功完成且没有错误，即表示当前数据和检索能力通过检查。

<details>
<summary><strong>安装器具体做了什么</strong></summary>

安装器会：

1. 根据当前系统和架构选择发布包；
2. 校验发布页中的 SHA-256；
3. 拒绝绝对路径、目录穿越、链接、特殊文件、大小写冲突和超量归档；
4. 按包内 `MANIFEST.tsv` 复验文件白名单、大小和逐文件哈希；
5. 运行 SQLite 能力自检并预先检查 Codex/OpenCode 配置；
6. 获取安装锁，安全切换程序目录，并保留用于失败恢复的旧版本；
7. 迁移旧记忆、重新生成本机索引并执行完整诊断；
8. 以可回滚方式接入检测到的 Codex 与 OpenCode。

任何步骤失败，安装器都会尽力恢复安装前的程序和接入配置，私人记忆目录不会因此删除。

</details>

## 下载来源与系统警告

只应从本仓库的 GitHub Releases 或本页官方脚本安装。当前公开包提供：

- 发布页 `checksums.txt`，用于发现下载损坏或内容不一致；
- 包内 `MANIFEST.tsv`，用于检查展开后的每个文件；
- SBOM 与依赖许可证集合；
- GitHub 构建来源证明，用于确认产物来自本仓库工作流。

> [!WARNING]
> 当前公开包没有 Apple Developer ID 签名、公证或 Windows 代码签名。Windows 可能显示“未知发布者”或 SmartScreen 提示。校验和与构建来源证明有助于验证下载，但不能替代操作系统代码签名。无法确认下载来源时，不要绕过警告。

## 文件位置

| 系统 | 程序目录 | 私人数据目录 |
|---|---|---|
| macOS、Linux | `~/.local/share/engramark/` | `~/engramark/` |
| Windows | `%LOCALAPPDATA%\Engramark\` | `%USERPROFILE%\engramark\` |

程序和私人数据刻意分开：重新安装只替换程序，不覆盖记忆。

## 升级与重装

升级或重装使用与安装相同的命令。安装器会先验证新程序，再切换固定程序目录；如果后续数据准备、冒烟检查或 Codex/OpenCode 接入失败，会恢复旧程序和旧接入。

升级完成后必须重启 Codex 和 OpenCode。已经运行的旧任务可能继续引用升级前的程序，直到应用重启。

升级不会覆盖：

- `cards/` 中的原始记忆文件；
- 编号状态和未完成事务等持久数据；
- 用户配置 `engramark.json`。

如果本机索引格式或运行能力发生变化，Engramark 会从原始记忆文件重新生成索引。

## 常用配置

配置文件位置：

| 系统 | 配置文件 |
|---|---|
| macOS、Linux | `~/engramark/engramark.json` |
| Windows | `%USERPROFILE%\engramark\engramark.json` |

普通使用者通常只需要关注：

| 配置 | 默认值 | 用途 |
|---|---:|---|
| `radar.budget` | `3` | 一次请求最多自动提供多少条简短提示 |
| `radar.cooldown_ttl_seconds` | `86400` | 同一会话中重复提示同一条记忆前的等待时间 |
| `opencode.request_radar_enabled` | `false` | 是否启用 OpenCode 自动请求提示 |

修改配置后，重新打开 Codex 或 OpenCode，确保接入重新读取配置。

<details>
<summary><strong>高级检索配置</strong></summary>

| 配置 | 默认值 | 用途 |
|---|---:|---|
| `search.query_timeout_ms` | `500` | 单次查找时间预算 |
| `search.high_threshold` / `medium_threshold` | `0.64` / `0.34` | 高、中置信度与拒答边界 |
| `search.preview_max_bytes` | `800` | 高置信第一条结果的正文预览上限 |

除非正在复验检索行为，否则不建议随意调整这些值。

</details>

## OpenCode 自动提示

OpenCode 通过自然语言保存和找回不需要额外设置。自动请求提示默认关闭，因为短提示可能随 OpenCode 对话消息保存在 `system` 字段中，并被主模型、标题生成或压缩流程看到。

确认接受这一边界后，可以把配置中的 `opencode.request_radar_enabled` 改为 `true`，再重启 OpenCode。当前已验收的 OpenCode App 版本是 1.18.11；未验收版本默认不开启自动提示。

`allow_unverified_version` 只适合升级后的临时兼容性复验，复验结束后应立即恢复为 `false`。

## 故障排查

### 安装后助手无法保存或找回

1. 确认已经彻底重启 Codex 或 OpenCode；
2. 运行[完整诊断](#验证安装)；
3. 确认当前任务从正确的项目目录打开；
4. 询问时带上项目、组件、路径或决定主题；
5. OpenCode 自动提示关闭时，直接自然提问仍然可用。

### Codex 无法识别项目范围

如果 Codex 没有提供可靠项目根，可以在受信任的项目目录中启用项目覆盖，然后新建 Codex 任务。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark host-setup \
  project-enable --project "$PWD"
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" host-setup `
  project-enable --project (Get-Location).Path
```

不再需要时，将 `project-enable` 改为 `project-disable`。命令只维护项目内 `.codex/config.toml` 中由 Engramark 管理的配置；已有同名配置时会停止，不会覆盖。

### 诊断发现未完成事务

恢复命令会检查未完成事务，并安全地补齐仍需执行的步骤；重复运行不会重复应用已经完成的操作。

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/engramark recover
```

Windows PowerShell：

```powershell
& "$env:LOCALAPPDATA\Engramark\bin\engramark.exe" recover
```

## 卸载

macOS 与 Linux：

```sh
~/.local/share/engramark/bin/uninstall
```

Windows：

```powershell
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Engramark\bin\uninstall.ps1"
```

卸载只移除程序和 Engramark 管理的 Codex/OpenCode 接入，始终保留私人记忆。程序不提供自动删除记忆的参数；确实不再需要数据时，请在确认备份后手工处理私人数据目录。
