# 架构设计

**[English](architecture.md) | [简体中文](架构设计.md)**

本文记录 Engramark 当前已经实现的架构约束，不作为未来功能愿望清单。测试门槛与实测结果见[测试与验收](测试与验收.md)。

## 1. 设计边界

Engramark 是本地、按需启动的长期记忆层，没有常驻服务。它为多个编码助手提供同一份卡片真源、派生检索缓存和统一 MCP 接口。

实现与发布矩阵包含 macOS arm64/x86_64、Linux x86_64 和 Windows x86_64。只有对应原生 CI 作业完成完整测试、能力探针、打包和安装生命周期后，该次产物才可视为受支持；不能用交叉编译代替原生验收。数据目录仅支持本地文件系统，NFS、SMB、云盘同步目录和可移动介质不在一致性承诺内。

## 2. 核心不变量

1. `.mem` 是记忆内容唯一真源；SQLite 只是本机派生缓存。
2. 会改变长期行为的状态必须持久化；诊断计数和会话冷却可以丢失。
3. 已分配编号永不复用；内容删除以墓碑表达。
4. 写入 API 成功返回后，新查询必须看到新值。
5. 显式检索失败必须报错；自动钩子失败时开放宿主流程。
6. 影响召回、过滤或排序的版本变化必须使旧缓存失效。
7. 内嵌 SQLite 与 Unicode 能力指纹不匹配时拒绝打开缓存，不在原缓存上降级结构。
8. 只有用户以任何语言明确表达长期保存意图时才写入记忆；按语义判断，不依赖固定关键词。宿主钩子只检索已有正式记忆，不记录会话或自行提议候选。

## 3. 数据与目录

```text
cards/                         记忆真源
state/id-sequence              编号高水位
state/transactions/*.txn       未完成事务的恢复证据
state/locks/                   跨进程协调
cache/memory.mcache            SQLite 派生缓存（v7）
~/.local/share/engramark/
  bin/engramark                所有宿主共用的单一原生二进制
```

`state/` 是持久状态，不能像缓存一样删除。`last-used` 影响新鲜度与排序，以卡片为权威；每张正式卡每天第一次通过详情读取路径读取时最多回写一次。搜索摘要、搜索预览和雷达注入保持只读，不把模型可能看到内容等同于明确读取详情。第一版不采集访问次数，避免每次读取产生缓存写事务。

## 4. `.mem v1`

- UTF-8、无 BOM、LF；读取阶段兼容完整 CRLF。
- 正文保留空行、行尾空格和 Unicode。
- 标题之前只接受已定义指令，未知指令拒绝。
- 实体按规范化键去重，顺序无语义。
- 可信度内部使用 0–6 的整数固定点，对外显示为 T0–T3 的半档。
- 语义哈希使用带格式版本、字段编号、类型和长度边界的规范编码。
- `F` 是派生展示值，不进入语义哈希；源文件另有逐字节 SHA-256。
- 格式升级只能通过显式迁移，并先生成原文件备份和统一差异。

状态机：

```text
candidate ──发布──> published ──归档──> archived
    │                    │                    │
    └──拒绝──────────────┴──确认删除─────────┴──> tombstone
```

所有卡片状态都位于 `cards/`。发布、拒绝、修改、归档和删除都原子替换同一文件；反馈把卡片与 `state/feedback/<编号>.mark` 放入同一可恢复事务，避免崩溃后同日重复计分。精确重复复用原编号；确定替代关系使用 `# supersedes @旧编号`，引用必须存在且不得成环。

## 5. MCP 语义边界与项目隔离

MCP 不接收 `.mem` 卡片全文。保存和提议使用 `title、body、entities、type、scope`，锁定只属于正式保存；核心层统一校验字段、建立 Card 对象并序列化线格式。正式保存默认 `I3/T3`，候选默认 `I2/T2`，`fact、decision、skill` 均为公开类型。AI 只有在用户明确要求“先存为候选”时才能提议候选。

更新采用字段级 PATCH：字段缺席表示保留，空正文和空实体数组表示明确清空。更新只允许修改标题、正文、实体和类型；编号、状态、来源、锁定、作用域、重要度、可信度、访问时间、有效期和替代关系由核心层保留。同值更新不写源文件、不提交事务，也不增加缓存代次。

MCP 搜索只接收非空自然语言 `query`，固定搜索已发布记忆并最多返回 5 条；分页、状态范围、项目参数和评分解释只保留在 CLI。最终置信度为高的第一名使用最多 800 UTF-8 字节的正文预览，其他结果保持最多 160 个 Unicode 码点的短摘要。SessionStart 的 `top --human` 始终使用短摘要，不继承搜索预览。MCP 与雷达输出使用“记忆编号 + 标题”的自然语言格式，`.mem` 卡头、`I/T/F`、原始 JSON 和内部异常不进入对话界面。

作用域是隔离边界：项目已知时只允许访问全局记忆与当前项目记忆，项目未知时只允许访问全局记忆。搜索、雷达、按编号读取、反馈、更新和生命周期操作都执行同一可见性判断，其他项目的记忆在召回前被过滤。项目卡被拒绝或删除后仍保留不含路径的范围标识作为墓碑路由元数据，避免墓碑编号跨项目变为可见。

项目上下文按顺序来自 MCP `roots` 的唯一文件根、具备项目标记的进程工作目录，或 Codex 受信任项目配置中的 `mcp_servers.engramark.cwd`。`/`、用户主目录、常用宽泛目录、系统临时目录、程序安装目录和记忆数据目录不构成项目。上下文未知时，项目范围写入明确失败，绝不静默降级为全局记忆。`engramark host-setup project-enable --project <目录>` 可显式加入 Codex 项目覆盖，`project-disable` 只撤销该托管块。

服务明确协商 `2025-06-18` 与 `2025-11-25`；未知版本返回服务端最高支持版本，而不是盲目回显。工具提供中文标题、严格 JSON Schema 和真实副作用注解。输入或业务错误以可自纠工具错误返回，未知工具和协议故障使用 JSON-RPC 错误。传输日志只记录请求元数据与字节数，不记录查询、标题、正文、实体、反馈理由或完整结果。

## 6. 并发与持久性

- 查询持有共享 `cache.swap.lock`，覆盖打开、查询和关闭全过程。
- 变更先独占 `mutation.lock`，再独占 `cache.swap.lock`。
- 锁顺序固定，所有锁都有超时。
- MCP 每次调用短暂打开 SQLite，不保留长期连接。
- 全量重建在同文件系统的私有临时目录建库，最终切换时才独占交换锁。

跨进程协调使用 Rust 标准库文件锁：Unix 对应 `flock`，Windows 对应 `LockFileEx`。锁文件拒绝符号链接与 Windows 重解析点，超时值只接受有限且有界的秒数。

临时文件在目标同目录以私有权限创建，写入后同步文件，再原子替换并同步父目录；macOS 文件同步额外使用 `F_FULLFSYNC`，Windows 使用受保护 DACL、`MoveFileExW` 与 `FlushFileBuffers`。当前 SQLite 固定使用 `journal_mode=DELETE`、`synchronous=FULL`、`foreign_keys=ON`、`trusted_schema=OFF`、`mmap_size=0`，macOS 额外启用 `fullfsync`。故障注入证明的是进程崩溃恢复；在具体硬件和文件系统上完成断电试验前，不宣称端到端断电认证。

## 7. 可恢复事务

每次变更按以下顺序执行：

1. 解析并验证计划后的完整卡片图。
2. 按固定顺序获取两个独占锁。
3. 写入带 UUID、自校验、前后哈希和恢复载荷的事务日志。
4. 原子替换 `.mem` 并同步文件与父目录。
5. 在一个 SQLite 事务中同步普通表、两个 FTS、雷达、缓存代次和 `applied_ops`。
6. SQLite 提交作为 API 写入线性化点。
7. 删除事务日志并同步父目录。

恢复矩阵：

| 源文件 | 缓存 | 处理 |
|---|---|---|
| 旧 | 旧 | 操作未开始，清理日志 |
| 新 | 旧 | 从源重放缓存 |
| 新 | 新 | 操作已完成，清理日志 |
| 旧 | 新 | 以 `.mem` 修复缓存并报告 |
| 其他 | 任意 | 停止自动恢复并保留证据 |

多文件事务按完整状态向量恢复；半完成状态利用日志内经哈希验证的载荷补齐。UUID 与 `applied_ops` 保证重放幂等。

## 8. 单二进制运行时

Codex、OpenCode、钩子、MCP 和 CLI 全部通过当前发布版本内的单一原生二进制 `bin/engramark`。公开安装包内含锁定工具链构建的 Rust 二进制与内嵌 SQLite，不使用用户电脑里的 Python，也不再有运行时下载、运行时重绑定或 Python 能力指纹机制。

公开安装把程序放在 `~/.local/share/engramark/`，私人数据位于独立的 `~/engramark/`。重装先运行二进制自检（SQLite 能力探针），原子切换程序目录并保留一个回退版本，然后迁移卡片并重建缓存；任一步失败自动恢复旧程序与旧接线。宿主接入在写入前预检配置。

缓存 v7 的元数据保存：

- `.mem` 格式版本与缓存结构版本；
- 表结构、查询规划器、规范化、分词器和雷达编译器版本；
- SQLite 精确版本、编译选项摘要与 STRICT、FTS5、trigram、contentless-delete、contentless-unindexed 能力探针结果；
- Unicode 数据版本、完整源集合哈希、构建 UUID、代次与完成标志。

派生缓存带旧能力指纹时，Engramark 会从记忆卡自动重建缓存。缓存不可跨机器复制使用；可移植边界是 `.mem` 与受控快照，目标安装可据此重新建立索引。

## 9. 检索缓存

普通表使用 STRICT、独立整数列和约束。缓存元数据分别记录：

- `.mem` 格式版本与缓存结构版本；
- 表结构、查询规划器、规范化、分词器和雷达编译器版本；
- SQLite 精确版本、编译选项摘要与能力探针结果；
- 完整源集合哈希；
- 缓存代次、构建 UUID、完成标志和有效日期。

Unicode FTS 索引完整标题和正文。trigram 索引标题、实体、锚点、网址、路径和代码标识符，不复制整篇长正文。

默认边界：

- 单卡最大 2 MiB；
- 查询最大 4,096 字符；
- 候选池 80；
- 单次查询预算 500 ms；
- 单次详情最多 5 张，每张最多返回 2,000 字节。

超时或缓存不可用时显式查询会失败，不会返回伪造的空结果。完整诊断会核对有效卡集合、普通表、两个 FTS、语义哈希和 FTS 自身完整性。

## 10. 雷达与宿主适配

雷达以 SQLite BLOB 保存自校验分区字节码，包含魔数、格式版本、编译器版本、规范化版本、状态数、边数、区段长度和 SHA-256。未知必需区段会使整个雷达对象失效；未知可选区段才允许跳过。

- Codex 钩子可以在用户输入阶段扫描雷达并注入短的自然语言记忆提示。
- OpenCode 安装默认关闭的最小请求雷达插件；显式开启后只读取已有正式记忆，不记录会话、工具或命令内容，也不创建候选。
- OpenCode 雷达只验收 App 1.18.11。它通过耐久的 `message.updated` 事件确认索引块确已保存，再提交冷却；消息未保存或块被其他插件改写时，短保留会取消或自动过期。
- OpenCode 命中的短索引会随该条用户消息的 `system` 字段保存；请求内容本身不进入 Engramark，雷达状态只保存会话哈希和实际预留或展示的卡号。
- 两个宿主共享同一原生二进制、卡片和缓存。

核心统一生成雷达行：每行最多 360 个 Unicode 码点和 900 UTF-8 字节，并包含最多 120 个码点的首段微摘要；宿主完整注入块最多 1,200 UTF-8 字节。宿主适配器只包装、校验和透传，不重新摘要或截断。冷却按卡片隔离，只在实际展示后生效；预算外卡片和共享同一锚点的其他卡片不会被连带冷却。

自动钩子捕获异常并继续宿主流程；显式 MCP 调用返回可见错误。这是故障语义差异，不是实现遗漏。

## 11. 安全、备份与 Git

- Unix 私有目录权限为 `0700`，卡片、状态和缓存文件为 `0600`；Windows 使用只授权当前用户、SYSTEM 和 Administrators 的受保护 DACL。
- 发布包拒绝绝对/上跳路径、链接、特殊文件、大小写折叠冲突和超量内容；解包后按 `MANIFEST.tsv` 复验白名单、大小与逐文件 SHA-256。
- `checksums.txt` 用于发现传输损坏，不单独作为发布者身份证明。标签工作流为四个原生产物生成 GitHub 构建来源证明并只创建草稿；当前公开包可以在全部原生验证通过后人工发布，但没有 macOS Developer ID 或 Windows 代码签名，操作系统仍可能显示来源或未知发布者警告。
- 缓存包含完整记忆，静态保护依赖 FileVault 等系统磁盘加密。
- 一致备份先恢复未决事务并持有变更锁，只复制卡片、编号状态和清单。
- 活跃 SQLite 不直接复制；诊断、备份与回滚使用受控接口。
- 回滚前自动保存当前安全快照，编号高水位只升不降。
- Git 排除真实卡片、状态、缓存、日志、锁、本机运行时和安装记录；本机遗留的历史目录（如旧版 `raw/`）也保持忽略，防止历史数据误入仓库。

仓库隐私边界由自动测试验证，但仍禁止使用 `git add -f` 绕过忽略规则。
