# 测试与验收

**[English](testing.md) | [简体中文](测试与验收.md)**

本文面向贡献者和维护者，回答两个问题：改完以后应该运行什么，以及一个版本公开前必须通过什么。全部行为测试使用临时目录，不读取真实记忆。

## 准备测试环境

从源码运行测试需要：

| 工具 | 用途 |
|---|---|
| Python 3 | 黑盒测试、打包和安装生命周期 |
| Rust 工具链 | 由 `rust/rust-toolchain.toml` 锁定，用于核心构建和测试 |
| Node.js 22 | OpenCode 适配器测试 |
| uv、ShellCheck、cargo-deny | 静态与供应链检查，只在完整门禁中需要 |

普通用户安装发布包不需要这些开发工具。

## 我改了什么，应该运行什么

| 改动范围 | 最小检查 | 何时还要扩大检查 |
|---|---|---|
| 只改 Markdown | `python3 tests/test_documentation.py` | 命令、安装步骤或发布边界变化时，再运行对应生命周期 |
| Rust 核心、卡片或检索 | `python3 tests/run.py` | 影响性能或召回时，再运行规模回归 |
| Codex/OpenCode 接入 | `python3 tests/run.py` | 改变安装接线时，再运行安装生命周期 |
| 安装、升级、卸载或打包 | 本机打包 + 安装生命周期 | 公开前必须等待全部原生平台 CI |
| 发布候选 | 完整门禁 + 10,006 张卡规模验收 | 必须通过四个平台构建和兼容性复验 |

## 日常完整测试

```sh
python3 tests/run.py
```

运行器先构建当前源码的调试二进制，固定所有黑盒测试使用这个路径，再执行 `cargo test --locked` 和 7 组黑盒测试。这样不会因为 `target/release` 中存在旧文件而误测陈旧二进制。

| 测试组 | 主要覆盖范围 |
|---|---|
| 文档 | 唯一一级标题、相对链接、中英文配对和关键说明一致性 |
| 核心 | 记忆生命周期、MCP、显式保存规则、项目隔离、反馈、隐私和并发写入 |
| 架构 | 事务恢复、本机索引、编号、备份和迁移 |
| Codex | 自动提示、摘要预算、冷却、不保存会话和失败不阻断 |
| OpenCode 自动提示核心 | 严格协议、预算、临时保留、耐久冷却、并发、负样本和性能门槛 |
| OpenCode 适配器 | 文本来源、命令跳过、消息事件、故障取消和真实核心端到端 |
| 宿主接线 | Codex/OpenCode 重复接线、旧接线升级、项目 `cwd`、插件和卸载 |

仓库隐私依赖真实 Git 元数据，所以在 CI 和发布前还要单独运行：

```sh
python3 tests/test_repository_privacy.py
```

## 金样兼容契约

`tests/golden/` 是原生移植完成时冻结的兼容契约，覆盖规范化、记忆格式、哈希、查询规划、检索、自动提示、扫描和错误语义。

Rust 测试会先按 `manifest.json` 校验文件集合与 SHA-256，再执行行为断言。契约变化必须经过明确评审，并同时更新金样、清单、实现和面向用户的文档。旧实现和金样生成器不再保留，避免用已经变化的实现重新定义自身契约。

## 规模回归

默认规模回归使用 2,000 张合成记忆，模拟多年手动积累：

```sh
python3 tests/test_retrieval_scale.py
```

它检查正确召回、无关问题拒答、项目隔离、自动提示误命中、查找与提示延迟，以及注入字节数。性能数字会随机器变化，脚本中的门槛才是验收标准。

发布前使用同一脚本运行 10,006 张卡的非 CI 验收：

```sh
ENGRAMARK_SCALE_CARDS=10006 python3 tests/test_retrieval_scale.py
```

## 打包与安装生命周期

必须显式选择当前机器能够原生运行的目标，不要依赖打包脚本的默认值。

| 当前机器 | 目标参数 |
|---|---|
| macOS Apple Silicon | `macos-arm64` |
| macOS Intel | `macos-x86_64` |
| Linux x86_64 | `linux-x86_64` |
| Windows x86_64 | `windows-x86_64` |

```sh
python3 packaging/build_release.py --target <当前原生目标>
python3 tests/test_install_lifecycle.py
```

生命周期在隔离用户目录中验证：危险归档拒绝 → 安装 → Codex/OpenCode 接线 → MCP → 自动提示 → 查找 → 写入 → 备份 → 升级重装 → 卸载，并确认卸载后私人数据仍然完整。

## 本地完整门禁

下面的命令与当前 CI 使用的检查保持一致：

```sh
python3 tests/test_repository_privacy.py
python3 tests/test_documentation.py
uvx ruff==0.15.4 check packaging tests
shellcheck install.sh bin/install.sh bin/uninstall bin/uninstall.sh
git diff --check
```

```sh
cd rust
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
cd ..
cargo deny --manifest-path rust/Cargo.toml check advisories licenses sources
```

## CI 与发布验收

持续集成在以下原生环境运行完整 Rust/黑盒测试、最终二进制能力自检、打包和安装生命周期：

- macOS 14/15 arm64；
- macOS 15 Intel；
- Ubuntu 22.04/24.04 x86_64；
- Windows Server 2022/2025 x86_64，并复验 Windows PowerShell 5.1。

Linux 发布包在 Ubuntu 22.04 构建，并拒绝高于 glibc 2.35 的符号需求；同一候选包在 Ubuntu 24.04 复验。四个平台全部完成前，不能把候选版本视为可公开发布。
